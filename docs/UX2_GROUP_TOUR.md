# UX2 group tour and feedback handoff

The public starting page is [`docs/demo-tour/index.html`](demo-tour/index.html). `docs/index.html` routes a GitHub Pages `/docs` site to that page. It contains only illustrative German role guidance. Its role buttons change text in the browser and do not call the Apps Script app or store state. A request link supplies `request`, `scenario`, and a Google Forms feedback URL; invalid values are ignored. Neither a participant case nor an admin action URL appears in the page.

In the owner-only Demo Hub, **Startlink vorbereiten** explicitly creates or reuses one feedback Google Form in the dedicated demo folder, then builds a group starting link for the selected persisted request. The Form has required fields for request ID, role, step, and observation. The request ID is prefilled in the owner-generated link; Google Forms records the submission timestamp. The Form is not a training completion form. Process & Quality retrieves only that request's feedback in **Ergebnisse & Register**. Trainer and participant work still uses each person's assigned Calendar invitation and verified-email training Form link.

The configured Pages destination is `https://mattbang.github.io/cosanum-automation/demo-tour/`. This URL is a future publication target, not a verified live page. Publish `/docs` from the reviewed branch only after approval and inspect it before sharing a generated link. Do not send the owner-only admin URL or share an owner password. The feedback Form may accept comments from anyone with its link; comments are not evidence, never update cases, and should be reviewed before display outside the owner app.

Local check: `node scripts/test_demo_tour.mjs` covers URL validation, role-tour no-write source, request/role/step/timestamp association, request-filtered retrieval, and Form creation retry after an interrupted Drive move. Existing tests should also pass.

Connected acceptance remains with the deployment owner: publish and open one group starting link in a test browser, verify the page contains only the request ID and generic handoffs; complete one trainer and one participant response under their assigned accounts through their personal links; submit one feedback item and retrieve it by request ID in the private register; compare request, event, proof, and skill counts before and after browsing the tour. Creating the live Form, publishing Pages, and submitting responses were intentionally outside this local increment.
