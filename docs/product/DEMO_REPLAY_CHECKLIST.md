# Integrated demo replay checklist

Copy this checklist into a **private run record** for each integrated replay. Keep account addresses, generated links, screenshots, hashes, and evidence outside the public repository. Mark each item pass/fail with the actual record ID or a private evidence link; do not report a simulated gateway as a connected check.

## Setup

- [ ] Record fixture version, run date/time, Apps Script deployment ID, Sheet ID, and test account allowlist in the private run record.
- [ ] Confirm five synthetic topics and demo skill entries; no production matrix is connected.
- [ ] Confirm `Europe/Zurich` display and actual calendar access for all selected test accounts.
- [ ] Reset only the synthetic fixture after preserving any prior test evidence.

## Main path

- [ ] Create a group request. Record request, session, and distinct person-case IDs.
- [ ] Show an allowed next-level progression and blocked skipped/blank/excluded examples with reasons.
- [ ] Show qualified trainer and theory/practice plan; theory must pass before practice can confer a level.
- [ ] Show at least two dates and varied free slots where possible; prove one seeded busy interval is excluded.
- [ ] Book one selected slot; record Calendar event ID, Zurich time, trainer/participant invitees, and one test inbox invitation. Retry without a duplicate event.
- [ ] Submit one verified trainer response per person and required phase; only attended + passed moves that phase to confirmation.
- [ ] Submit one verified affirmative participant response per person and required phase; reject wrong-account and duplicate attempts without closing another case.
- [ ] Generate separate Docs/PDFs and source links for each person; rerun without duplicate proof versions.
- [ ] Verify Drive and local PDFs have matching SHA-256, readable copies, manifest, and index entry.
- [ ] Apply only the explicit demo target level once. Replay without an extra level increase.
- [ ] Send one completion notice only after the final selected case completes; verify recipient and ledger key.

## Exceptions and recovery

- [ ] Decline one group invitation: that person's case is flagged, the rest of the event remains.
- [ ] Leave one RSVP unanswered: show the prior-business-day flag without marking the person absent.
- [ ] Mark one participant absent or not passed: no confirmation request, proof, or level raise.
- [ ] Leave an attended + passed acknowledgement open: simulate day +2 and +5, one reminder each, then Daniel's open-case alert; no completion notice.
- [ ] Interrupt or corrupt the local archive copy: case remains pending/error, no skill raise or completion; retry to one verified manifest.
- [ ] Change a demo Sheet level while a case waits: show conflict rather than overwriting.
- [ ] Filter audit view by topic, person, request, and open status; open event, both Form responses, Drive proof, local archive reference, skill change, and message ledger.
